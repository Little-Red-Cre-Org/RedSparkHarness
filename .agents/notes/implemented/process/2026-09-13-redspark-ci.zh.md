# Agent Note: RedSpark 仓库自动化

Status: implemented

[English](2026-09-13-redspark-ci.md) | 中文

## Problem

上游自动化依赖本分支尚未配置的专属 runner 池、部署账户、服务商凭据与组织管理配置。

## Decision

RedSpark 在标准 Linux 和 Windows runner 上运行无需密钥的客户端基础检查。两个系统均执行构建、类型和客户端测试；Linux 另执行 lint 与文档检查。工作流权限只读，检出不持久化凭据。原生扩展、沙箱和文件名工作流保持启用。仓库设置停用其他上游工作流，不删除其定义或失败记录。重新启用集成前必须检查目标账户、凭据与 runner 要求。

[RedSpark 工作流](../../../../.github/workflows/redspark-ci.yml) 在构建前运行工作流回归和仅依赖源码的包发布规则检查。lint 与文档检查在类型准备后、运行时回归和客户端测试前执行，因此静态检查失败无需等待这些测试。main 分支保护及其规则集要求 Linux/Windows 的源码检查和打包检查均通过。现有作业名称是这些设置的稳定标识；源码构建成功不能替代打包消费端的验证结果。

打包作业为 dsh 包族使用现有打包器的有界工作池，并发数为四。每个 tarball 仍单独校验内容，记录的发布顺序遵循发布依赖顺序，不受完成先后影响。普通构建与官方构建继续分开，因为两者的客户端 profile 不同；需要凭据的发布流程保留现有设置。

原生扩展的 push 检查和沙箱矩阵监听本 fork 的默认分支 `main`。原生扩展的 PR（Pull Request）路径过滤和沙箱合并后运行的平台策略保持不变。停用的上游工作流保留其参考分支和集成设置。

普通 Dependabot 版本更新 PR 的开放数量上限为零，安全告警不变。分支清理关闭未合入的依赖更新 PR 并删除其远端分支，不会将依赖变更合入 main，也不保留本地备份。

## Alternatives considered

**关闭所有检查：** 这会同时隐藏代码失败与缺失的集成。RedSpark 保留可执行的客户端基础检查，以及独立的原生扩展和沙箱检查。

**替换上游账户名称并继续启用所有作业：** 品牌改名不能提供凭据或专属 runner。上游定义继续作为参考，保留其故障切换与不受信任 PR 防护。

**保留串行打包或复用普通客户端构建：** 串行打包会延迟各平台的消费端验证；小规模有界工作池缩短这部分工作，同时保持发布包集合不变。复用不同的客户端 profile 会违反官方产物校验要求。采用新的并发数前，必须对比串行运行，确认 tarball 内容和发布顺序一致。

## Consequences

基础检查无需服务商调用或部署即可为 RedSpark 提供托管验证。打包检查在仓库外的全新消费端安装 tarball，并在两个系统上运行现有打包 e2e。沙箱平台失败在合并后发现。基础检查不声称具有上游 CI 文档描述的完整覆盖率、浏览器快照、SDK 平台矩阵或真实 API 验证能力。既有上游 runner 记录仍服务于保留的工作流定义，本记录负责该分支的启用与调度策略。[工作流回归](../../../../rsh/Scripts/ci-workflow.spec.ts) 在启用的 Linux 基础检查中验证 main push 路由和静态检查顺序。
