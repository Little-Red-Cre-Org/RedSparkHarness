# Agent Note: Persistent Agent task scheduler

Status: implemented

[English](2026-09-15-agent-task-scheduler.md) | 中文

## 问题

已有 Schedule 插件只向活跃的所属根 Agent 交付提醒。独立定时编码任务需要保存计划、暂停恢复、执行记录和启动恢复，且不能要求原对话一直打开。

## 决策

显式暂停在同一事务中保存定时计划的剩余等待时间与状态。恢复根据持久保存的剩余时间计算新的执行时间，避免暂停期间经过的时间触发补发提醒。绝对结束时间保持不变。

目标模式组合已有目标领域与轮次驱动器，不通过定时器反复改代码。计划保存目标和验收标准，认领在执行开始前保存执行会话身份。完成判断依据持久化目标状态。用户明确继续时恢复原会话，保留验证信息，并给予有界的追加轮次。结果不确定的中断不自动重放。SQLite schema 4 增加可选目标字段并保留旧定时任务。

按需启用的 [task-scheduler](../../../../packages/automation/task-scheduler/README.zh.md) 插件拥有独立 SQLite 计划与记录数据库。事务先认领一次执行并推进下次时间，再创建执行会话。错过的周期合并，已认领的单次不重放。过期认领标记结果不确定并暂停任务。只有执行适配器依赖 Agent 工厂、预设、工作区、权限与会话服务。每次使用新的普通会话，保存真实执行过程和持久化轮次结论。

范围工具从创建它的根会话继承工作区、模型与预设。定时执行会话不能再调度子任务。发布配置不会静默启用任务。卸载移除工具、取消并等待所属运行结束，保留计划。`completed` 仅表示 Agent 轮次持久结束，不表示代码测试通过。

## 提醒出口

侧边栏提醒列表和未读数量展示已提交的到点及结果记录，无需让模型承担界面投递。客户端独立于设置页持有一个可释放的轮询器；系统通知只在授权后补充应用内弹窗。SQLite 第二版将确认状态与执行记录分开，确认到点卡片后保留已读，后续结果更新同一卡片。客户端独立于已读标记观察阶段变化，投递一次系统结果通知，不再增加第二张卡片。列表保留最新 100 条，确认记录随执行记录一起清理。这样不把调度器绑定到 Electron，代价是连接客户端的轮询延迟和系统投递限制。测试覆盖迁移、重启已读、结果新提醒、防重复弹窗、系统拒绝和卸载；真实 Loader 检查执行产生的提醒与确认。

## 考虑过的替代方案

**扩展会话提醒：**其显式 live-owner 约定与 v1 事件流服务于另一用途。改变冷会话唤醒会静默改变已有提醒；独立插件保留原行为。这是新增能力，不取代 durable-web-schedule 决策。

**在 AgentLoop 中添加定时器：**会把持久化、启动恢复与编码循环耦合，不利于计划中的架构重构。

**重放所有错过或中断的执行：**外部代码修改与请求无法同本地记录原子提交。自动重放可能重复产生副作用，因此中断任务需要先检查。

## 后果

计划在重启后保留，不依赖原对话处于活跃状态。SQLite 事务协调多个认领方，执行过程仍是普通会话。代价是自动准入至多一次，而不是外部操作恰好一次：认领后、提交前崩溃可能丢失该次执行。执行要求应用运行。第一版不包含日历 cron、外部通知及任务和会话总量保留策略。Agent 结束不证明验证成功。

## 测试

存储测试覆盖双连接认领、周期对齐、所属会话隔离、暂停删除、过期恢复与保留限制。运行时测试覆盖异步结论、失败、超时和等待完成的卸载。真实 Loader 组合加载正式 Agent 循环、持久化、预设、工作区和权限服务，仅替换模型传输；通过真实工具创建任务，验证持久化执行记录和模型可见描述快照。

## 图形管理扩展

全局和会话历史响应均从保留的任务定义（包括删除标记）解析提醒开始时间。Host 负责此投影，避免可见任务筛选改变历史含义。客户端直接使用投影时间，无法获取时留空。存储重开测试、真实 Loader 创建／执行／删除流程及历史渲染快照覆盖删除回归，不改写执行记录。

可选设置插槽提供创建、暂停恢复、确认删除和运行记录，无需修改界面外壳。生成的 Typert Remote 网关与工具共用归属校验和创建规则。客户端控制器串行处理操作、显示保存失败，并在卸载后抑制迟到状态更新。四项控制器测试与真实 Loader 网关归属测试之外，还在桌面客户端用远期任务验证创建、暂停、恢复和删除；验证后删除测试任务，全程不调用模型。

## 有界计划窗口

历史按秒精度显示每条执行记录保存的时间戳。直接提醒详情显示计时开始时间和生成时间，因为即时完成提醒不是用户等待的开始。后续周期使用上一个间隔边界；没有计时信息时使用已记录的实际执行开始时间。生成记录不能证明通知已经可见。Agent 工作保留三个时间戳；大于零但不足一秒的耗时显示为“不足 1 秒”。包内渲染快照覆盖两种模式、尚未结束的运行和不同记录间的切换；不会通过改写存储时间制造耗时。

管理界面分组展示创建、计划和实际运行记录。可选结束时间不包含该时刻，停止后续启动及恢复补执行，允许已调度的工作结束。这保留了用户选择的“计划窗口”与“强制取消执行”的区别。可选 JSON 字段保留已有无限期计划。边界、过期启动、时区与运行中任务测试固定此行为。

提醒删除使用 schema v3 中的执行批次删除标记，保留调度记录并屏蔽后续完成状态更新。侧栏删除复用已有持久化归档机制，并明确保留执行会话记录。两处操作均要求确认，失败时显示错误供重试。

Windows 通知显示回执不能证明用户看到了横幅。因此桌面预加载脚本向经过身份校验的主应用页面提供有长度上限的纯文本提醒请求。桌面壳窗口在主屏工作区域右下角显示转义后的文本，不抢占焦点；结果共用一个有界窗口，独立显示并在 20 秒后关闭，退出应用时释放。

## 自然语言时间安排

定时任务默认从任务内容识别固定间隔、相对等待、固定持续时间和手动停止条件。创建页只显示一行可核对的计划摘要；周期、间隔和结束条件收进“调整时间”。描述中的明确规则是权威来源，对应手动字段只读，避免“描述写 5 分钟、输入框填 10 分钟”的冲突。未识别到时间时不会静默立即执行，而是要求补充描述或打开手动设置。周期计划固定以创建成功时刻计时，不提供单独起始时间，满一个完整周期后首次执行。

解析和 Host 准入使用同一套校验：`每5分钟`、`每半小时`、`持续1小时`、`直到手动停止`会固化为数值规则；多个周期、缺少单位、持续时间不长于周期和描述／表单冲突会被拒绝。每天和每周的北京时间固定时刻取下一次执行时间，不额外叠加倒计时；具体截止时刻独立解析。按月、按年、工作日、节假日和按次数结束的规则会被拒绝，不做近似换算。引号内的文本不定义时间；提醒之前的执行动词保留 Agent 执行语义。
