# Agent Note: 代码编辑器与任务对话使用独立的 IDE 区域

Status: implemented

[English](2026-10-16-ide-editor-layout.md) | 中文

## 问题

作为首个编辑器标签打开的对话占用了编写代码的空间。仅在悬停时显示的新建文件按钮让空工作台难以上手。

## 决策

Desktop 适配器在 Code OSS 右侧辅助栏注册保留状态的 WebviewView。代码文档和修改记录比较使用第一个编辑器组。资源管理器提供「新建文件」，默认常显标题栏操作。空编辑器组会打开未命名文档；已恢复的标签保持原样。现有 Desktop 消息通道和保存职责保持不变。

## 考虑的替代方案

**将对话放入第二个编辑器组**仍会与文件标签竞争，并允许编辑器导航替换对话。侧栏为对话提供了可独立隐藏的区域。

**自建编辑器和文件树**会重复 Code OSS 的编辑、新建文件和保存能力，没有增加当前需要的能力。

## 影响

用户可以同时查看代码和对话。新建的未命名文档在保存时需要选择位置。已有布局偏好仍由用户持有。适配器定向检查覆盖空编辑器与已恢复标签、任务传递和工作区刷新；隔离 Code OSS 检查验证新建文件、中央编辑及磁盘保存，不调用模型。

回答代码复用现有私有消息通道，并打开新的未保存编辑器文档。Chat 投影负责完成及中断语义，首次加载时已完成的轮次作为历史基线。Markdown 解析器从后续已完成轮次的最后一条助手消息提取代码，桌面适配器校验消息后打开文档，不隐式写入文件或执行代码。

应用菜单在点击时向主渲染器读取当前选择，复用工作区菜单的草稿校验。桌面端只保存上次目录路径，避免未选中会话时恢复过期草稿。
