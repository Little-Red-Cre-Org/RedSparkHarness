# Agent Note：围绕问题理解图片

Status: implemented

[English](2026-10-10-image-understanding-relay.md) | 中文

## 问题

纯文本主模型无法查看上传的图片或图片工具结果。把整个任务切换给视觉模型会改变用户选择的执行路由，而通用图片描述可能遗漏任务需要的细节。

## 决策

[官方 NativePlugin](../../../../rsh/Modules/Official/image/image-understanding/README.zh.md) 通过原生能力接口提供独立读图能力，Engine 仅保留接口和 Program 接入点。Native headless 传入当前用户问题和原图，持久化理解结果，再通过现有 Session surface 操作替换模型可见的图片。原始事件仍用于展示和后续追问，已配置的主模型路由保持权威。视觉调用不携带工具，将图片中的指令视为不可信内容，并将提供方上报的用量与主模型输出分开记录。失败会明确反馈。

## 证据

四个参数化 Native Host 组合用例覆盖视觉主模型直读、纯文本主模型转接、针对原图追问，以及缺少终止消息的流。检查重新打开并重建持久会话，模型路由与理解文本保留在所属包的快照中。这些测试模拟外部模型提供方。真实提供方的准确性、定价和桌面交互需要另行配置凭据，不能从这些检查推断。

## 考虑过的替代方案

为整个任务切换主模型会改变已选执行器及其工具行为，一次通用描述又容易遗漏问题所需的细节。所选插件保留主模型路由，并允许针对原图反复提出问题。

## 影响

每次图片理解增加一次模型调用及延迟。文字描述可能遗漏视觉细节，因此 `understand_image` 工具允许针对当前会话原始附件提出新问题。首版使用一个明确的视觉路由和响应 token 上限，不包含模型择优框架、OCR 流水线或自动裁图。旧 Cordis 入口保留原有图片行为。
