# Agent Note: Native 会话在工具或子级失败时记录什么

Status: implemented

[English](2026-11-10-native-failure-facts.md) | 中文

## 问题

把录制会话迁到 Native profile 的过程中，暴露出四处 Native 运行时丢失了兼容层本来会记录的事实。它们都不会让正常路径失败，所以才能一直存活：每一个只在出问题时才显现，而出问题时暴露的恰恰是持久日志事后该解释的东西。

- 模型调用失败抵达 `turn/end` 时是 `code: UNKNOWN`。适配器其实已经分类过——`AUTH`、`RATE_LIMIT`、`SERVER`——是 Native 执行器重抛时把分类丢了。
- 钩子记录自己的审计事件时直接写 Session，绕过了应用唯一的待写批次，于是下一次持久化报 `append seq mismatch`。
- subagent 工具把子级的完整内容交给了父模型，包括其 reasoning 块。
- 提前停止的子级被报成 `Subagent ended: <reason>`，用内部标识符代替了可读原因，并丢弃了子级的部分输出。

后两条比看起来严重：第一条把子级私有的思维链泄进父级上下文；第二条告诉模型「某个东西结束了」，却没说子级是拒绝了、被截断了，还是出错了。

## 决策

按兼容层的方式逐条记录，并让录制会话去证明它。

**回合失败保留已分类的 code。** `native-model-execution` 重抛适配器的 `LlmError` 而不是裸 `Error`，回合边界从任何 `HarnessError` 读取 `code`，不再硬编码 `UNKNOWN`。对真正未分类的抛出仍保留兜底，所以该字段始终是全的。

**拦截器通过应用的 appender 记录。** 拦截事实携带该调用的 `appendEvent`，两个钩子桥接都通过它写 `hook/invoked` 与 `hook/result`。应用拥有唯一的连续待写批次；绕过它的事件不只是顺序不对，而是会让**下一次**持久化失败。

**子级结果就是它的文本。** subagent 工具在渲染前把子级输出过滤为文本块，与兼容工具一致。推理留在子级自己的日志里，也就是它被记录的地方，不成为父级上下文。

**未完成的子级要说明发生了什么、产出了什么。** 每个停止原因使用兼容层的标题（`hit its token limit before finishing`、`declined the task`、`was cancelled`、`failed`，以及可合并扩展原因的具名兜底），并把子级的部分文本保留在**同一个块**内——这正是兼容结果渲染的形状。

## 影响

失败的回合现在说得清原因：Web 客户端既有的 `AUTH_STATUS` 匹配器重新能识别凭据失败，运维读冷会话时不必靠模型可见的散文就能区分过期密钥和限流。

钩子可以执行策略并记录它执行过。此前，一个拒绝调用的 `PreToolUse` 钩子会破坏日志刷写；录制场景 `hook-cc-pretool-deny` 现在正好覆盖这条路径。

父模型看到子级的答案而不是它的推理。对 Native 工具而言这是一次行为收窄：一个靠推理得出简短答案的子级，不再把那段推理交给父级。

被截断的子级仍然贡献它的部分答案，因此父级可以基于子级实际产出的内容行动，而不只是知道它停了。

## 备选方案

- **保留 `UNKNOWN`，让消息承载诊断。** 否决：code 才是持久日志和 Web 客户端分支的依据；匹配消息是字符串启发式，而 Web 客户端本就有一个按兼容行为写好的、以 code 为形状的匹配器。
- **把 `appendEvent` 加在桥接自己的接口上而不是拦截事实上。** 否决：拦截事实是注册表交给每个拦截器的东西，任何记录审计事实的拦截器都需要同样的能力。放在桥接上会让第二个桥接重复实现。
- **继续透传子级所有块，指望父模型忽略推理。** 否决：兼容工具从不这样，而且模型并不能可靠区分「子级的私有推理」和「我应该使用的上下文」。
- **未完成子级只报标题。** 否决：那会丢弃子级实际做过的工作，而兼容工具会保留它。
