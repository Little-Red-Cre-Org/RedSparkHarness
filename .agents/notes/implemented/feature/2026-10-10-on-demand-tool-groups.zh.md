# Agent Note: 按需开放 Native 工具组

Status: implemented

[English](2026-10-10-on-demand-tool-groups.md) | 中文

## Problem

将所有已安装工具交给模型会增加请求体积，并引入与任务无关的选项。静态作用域限制无法在 Session 中逐步开放能力，也无法重建后续请求实际可见的工具集合。

## Decision

[tool-groups 插件](../../../../rsh/Modules/Official/guard/tool-groups/README.zh.md)提供初始工具列表、简短组目录和 `request_tool_group`。开放记录包含来源 Session 与确切工具名。Native headless 在每次模型请求前捕获工具选择，持久化变化后的请求头。注册表可见性统一控制 schema、程序绑定和执行准入，包括同作用域贡献。应用内置工具绕过注册表，因此与此模式不兼容。

当前批次不能使用自身刚产生的开放记录。新建和分叉 Session 从初始集合开始，恢复的 Session 重建自身开放记录。稳定的初始提示词部分避免恢复时系统提示词变化，申请结果提供新增 schema。开放工具组不替代审批或沙箱检查。

注册表在注册时将初始能力复制到 Set，后续调用方修改数组不会扩大初始集合，可见性读取复用该 Set。所有策略成功后才发布请求选择，结果按 Agent 作用域隔离。恢复时取已记录工具与当前组成员的交集：新增工具不会自动获得授权，删除的工具在下一次恢复请求中不可用。

## Alternatives considered

手动切换模式需要用户介入普通工具发现流程。自动阶段分类增加推理决策，并带来含糊的阶段回退行为。仅过滤 schema 会留下直接调用和嵌套执行绕过限制的路径。这些方案不在本次实现中。

## Consequences

此可选插件不需要新的推理服务或执行循环。部署配置负责明确分组和安装顺序。动态 schema 可能减少初始 token，也可能增加一次模型往返并影响前缀缓存。本地 Native 应用检查和 CLI 会话回放使用离线模型，不能证明付费模型的实际节省或桌面视觉验收结果。
