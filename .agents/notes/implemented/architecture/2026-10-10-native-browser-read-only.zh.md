# Agent Note: 由浏览器管理授权的 Native 只读工具

Status: implemented

[English](2026-10-10-native-browser-read-only.md) | 中文

## 问题

读取已登录浏览器页面需要用户的标签页权限与撤销语义。匿名 HTTP 抓取不具备这种授权。复用浏览器自动化桥接还会暴露本功能范围之外的导航和修改能力。

## 决定

[浏览器包](../../../../rsh/Modules/Official/web/browser-read-only/README.zh.md) 将共同演进的服务定义、本地提供器与工具消费者放在一起。Chrome `activeTab` 扩展管理明确的文档授权。Native Messaging 将扩展固定来源绑定到私有转发程序；每次启动生成的令牌用于转发程序连接本地管道时认证。发现文件须位于系统用户的私有目录，独占创建，不覆盖或复用崩溃残留文件。转发程序仅转发有上限的消息帧，不拥有 Harness 应用或 Session。

导航、刷新、关闭标签页和断开连接时，扩展撤销授权。读取结果须仍匹配有效授权、文档与网址。超时、取消或移除使待完成结果的接收方失效。重连必须重新授权。浏览器授权适用于所连接的 Host；具体会话的现有审批服务还须单独批准读取。现有工具流程在后续模型使用前记录来源文本、错误和审批决定。网页文本不可信；工具协议没有 Cookie、表单值、点击、输入或导航操作。

显式选择的 Native Desktop 会话可通过桌面私有通道进入现有 Code OSS 工作台。Native Client 实现同一任务及纯文本交接消息，校验父窗口、消息通道和会话工作目录，继续复用原 Host 的工具审批与 Session 写入方。源码开发的 linked-profile 标记对 Native 包和旧 bundle 均生效；打包应用仍要求包位于受限安装目录。这使浏览器工具能在该 Native 会话中使用，无需 Cordis 桥接，也不改变日常默认 profile。

浏览器操作与管道消息具有各自的异步边界。帧上限按单条消息计算，避免流批量交付时拒绝合法消息。接收器只在验证帧头后分配声明大小的正文，每个分片仅复制一次，避免重复复制累计帧内容。授权在文档验证及当前授权数量检查后提交，替换失败时保留原授权。弹窗命令按顺序执行，轮询时未变化的页面控件保留键盘焦点。

## 考虑过的替代方案

HTTP 抓取提供器不能代表已登录的浏览器文档。具有修改能力的自动化桥接会削弱只读承诺。第二个 Session 写入方或模型客户端会拆分持久化权威。浏览器全站权限比主动点击一个标签页授权更宽。重连后保留授权会掩盖文档身份丢失。这些方案均不采用。

## 影响

Windows Chrome 需要一次本地注册和一个已解压扩展。读取同时需要浏览器授权与会话审批。撤销停止后续读取，不删除已经持久化或发送的内容。仅支持顶层文档文本；其他浏览器内核、框架提取与网页操作需要独立决策。本地组件不要求服务订阅；所配置的模型调用仍可能收费。

[Web 能力决策](2026-06-24-web-capability-seam.zh.md) 继续管理公共搜索与抓取。其提供器选择依据没有被取代；本能力采用不同的授权权威。
