# Agent Note: 原生工作区指令

Status: implemented

[English](2026-10-05-native-workspace-instructions.md) | 中文

## Problem

原生 Program 需要与 Cordis 插件相同的工作区指令发现、优先级和持久化协调。文件系统代理身份与入口各自的消息来源声明不能定义指令权威。

## Decision

原生指令 Provider 与 Cordis 插件共享一个负责发现、优先级、摘要去重、渲染和持久化协调的组合器。Session 用户消息保存指令文本及来源事实；元数据缓存不会成为指令权威。

Program 在获准请求准备期间持有指令读取，并在模型分发之前追加返回的上下文。持久化原生工具结果观察器只保存路径，不启动异步投影工作。嵌套程序调用将成功文件访问传播至已接纳的外层调用；下一请求在外层步骤结束之后执行发现。安装取消通过请求信号中止发现，释放结果观察器后关闭文件访问记录入口。

即使 Cordis 返回新的文件系统代理身份，组合器仍由安装持有。每个请求明确选择 Provider。消息来源贡献者扩展声明该类型的 `dsh-llm/message` 导出，原生与兼容入口重导出该映射。

## Consequences

原生指令准备使用唯一 Session 写入者与选定的文件系统 Provider。持久化指令来源控制冷恢复，已接纳的文件结果启用嵌套目录发现。恢复从已提交的文件系统调用及其关联成功结果重建发现提示，并匹配调用身份、轮次和步骤；不写入独立路径历史。原生入口不安装 Cordis 服务，也不持有独立历史。

## Alternatives considered

在原生安装器中复制发现和协调逻辑会形成两套优先级及预算实现。后台指令读取需要额外的取消和完成状态持有者，因此原生 Provider 在请求准备期间执行读取。
