# Agent Note: 原生 Web 跟随确切 Host 准入

Status: implemented

[English](2026-10-05-native-web-session-follow.md) | 中文

## 问题

仅在结算后刷新对话，无法在 Host 轮次运行期间显示已接受的 Session 事实或助手文本。浏览器断连不能在持久化清理前释放执行所有权。

## 决策

选定 Connection 为功能自身拥有的 SSE 路由提供经过身份验证的 Fetch 响应。既有轮次准入拥有有界跟随队列；路由验证确切 Session 与准入身份，只允许一个跟随者。不引入第二个 Agent、Session writer、job registry 或重连调度。

执行器分别转发已接受的持久化事件和临时助手文本。Host 未读队列与活跃跟随者均有显式配置限制。队列超限取消确切轮次并使结算失败；解除跟随释放未读数据和跟随者槽位。Host 释放关闭流并排空既有执行所有者。

Client 使用维护中的 eventsource-parser 分帧与既有 Session 解析器。帧错误、过早 EOF 和观察者失败均取消已准入轮次并等待持久化结算。调用方中止解除流，但不能在 writer 清理前完成提示。缺少 Fetch 响应能力的载体在准入前拒绝带观察者的提示。

页面通过共享转录投影追加持久化事实。临时文本受可见尾部长度配置限制，并明确显示截断标记；持久化助手记录到达或结算刷新历史时清除临时文本。事件数量配置拒绝超量呈现状态。冷恢复只读取持久化历史。

## 考虑过的替代方案

**轮询状态或历史。** 重复读取无法标识真实输出进度，且会创建另一个调度器。

**应用 WebSocket 总线。** 第二套传输会重复 Connection 已拥有的认证与卸载机制。功能自身拥有的 SSE 将分帧和确切准入发送保持在本功能内。

## 后果

显式 native-web profile 提供 Host 队列／跟随者限制、Client 解析限制和呈现限制。既有显式原生配置必须提供这些必填字段；旧默认组合保持不变。工具卡片、审批和问题回复及其他模型片段呈现仍属于独立 Consumer。

既有真实 HTTP 用例覆盖增量文本、持久化事件发送、确切准入拒绝和延迟取消清理。一个有界队列用例覆盖超限与解除跟随。已构建 Chromium 场景通过随附 Client 组合记录临时助手输出、持久化结算和冷恢复。
