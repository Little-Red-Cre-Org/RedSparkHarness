# Agent Note：原生终端 Session 所有权

Status: implemented

[English](2026-10-05-native-terminal-session-owner.md) | 中文

## 问题

交互式原生终端需要恢复与取消，同时保持唯一 Session 执行权威。

## 决策

原生终端通过选定的 Session 执行 Provider 和共享原生执行器接收有界、带标识的输入。它拥有展示与输入取消，不创建第二个 Agent 循环或 writer。已接受的持久事件产生完成后的消息行。取消等待模型结算；普通退出先排空已接受工作，再卸载 Ink。

## 考虑的替代方案

复制兼容 runner 会保留 Cordis 所有权并重复执行。共享 Ink 展示作为库保留；原生 Program 提供窄输入接口。选择器与策略面板需要各自的原生 Consumer，不属于首个交互闭环。

## 后果

独立控制器拥有输入队列、取消、恢复与排空；既有终端生命周期场景直接验证其参数化执行区间，业务保留逐文件覆盖率要求。真实 TTY 与 Session 快照验证子进程交互；单元进程 V8 不能观察的薄 Ink 启动层和纯展示按拥有方排除。共享展示沿用兼容测试，不新增模型状态。

## 验证

一个无密钥真实 dsh 终端场景覆盖工具结果、排队多轮输入和同一 Session 的冷恢复。一个真实 TTY 回归在取消后阻止模型清理完成，验证普通退出等待释放。既有兼容展示测试覆盖共享格式和过滤。
