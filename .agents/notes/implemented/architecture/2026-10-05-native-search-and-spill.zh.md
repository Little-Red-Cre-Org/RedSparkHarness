# Agent Note：原生搜索通过选定 spill Provider 保留完整结果

状态：已实现

[English](2026-10-05-native-search-and-spill.md) | 中文

## 问题

显式原生配置需要在不加载 Cordis 运行时的情况下使用已有文件发现工具。被截断的搜索结果必须保留可读取的完整结果定位符，不能丢失省略的匹配。

## 决策

兼容和原生 Consumer 共用 ripgrep 执行、参数解析、采样、保留与格式化逻辑。原生注册使用选定的 Tools 和 subprocess Provider，取消和超时等待进程结束。原生 spill 存储通过独立于框架的 Definition 复用已有私有本地写入和清理流程。Consumer 仅在结果策略结束后保存已接受且未替换的直接调用结果。Session 拥有者在下一次模型请求前记录最终文本及搜索元数据。

## 考虑过的替代方案

复制搜索执行逻辑会让两个运行时的解析及输出发生分歧。仅保留未保存提示会丢失完整结果读取能力。加载兼容存储服务会使原生依赖图继续包含 Cordis。

## 影响

显式原生模板安装本地 spill Provider，兼容默认装配不变。搜索仍通过进程访问本地工作区，并非远程文件系统实现。spill Provider 释放时等待保存和启动清理完成。嵌套调用及被策略替换的结果保留已接受的内容，不新增 spill 产物。定位符可通过原生 grep 搜索，其他文件系统 Consumer 负责各自的访问限制。Client 搜索卡片及通用 spill 结果策略由其他迁移模块负责。
