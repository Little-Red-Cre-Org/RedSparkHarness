# Agent Note：原生 ACP 图片准入

Status: implemented

[English](2026-10-05-native-acp-image-admission.md) | 中文

## 问题

ACP 图片提示需要与其他原生 Program 输入共用标准化、限额与持久引用。传输层独立存储图片会使模型输入与 Session 重建分离。

## 决策

ACP 承载层将按顺序排列的文本和已配置位图块映射到所选附件 Provider 的既有批量准入。图片准备之前，它在精确空闲执行所有者中通过模型目录检查 Session 下一步的模型选择。非法或不支持的输入在用户消息准入前拒绝。既有执行器的取消和释放将图片准备与执行保留到结算完成。

初始化仅在附件与模型目录 Provider 均安装时声明图片支持。能力声明不会覆盖所选模型声明的输入模态。Session 存储已准入的图片引用；模型准备通过既有附件生命周期解析图片说明与字节。

## 考虑过的替代方案

没有持久附件引用的内联传输字节无法冷重建。独立 ACP 图片解码与限额会重复所选 Provider 的策略。声明音频、嵌入上下文或缺少的交互通道会使客户端依赖不支持的请求。

## 后果

ACP 通过显式原生 profile 接收按顺序排列的文本／图片提示，兼容默认配置保持不变。音频、嵌入内容、MCP 挂载、可变模型控制、人工交互与附件展示保留为独立批次。录制的模型输入预期核对存储图片的精确字节与生成的说明，只替换已验证的临时文件路径。
