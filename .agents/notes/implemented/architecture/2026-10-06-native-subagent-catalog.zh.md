# Agent Note：原生子任务目录

Status: implemented

[English](2026-10-06-native-subagent-catalog.md) | 中文

## 问题

Agent 需要在自身回合结束及进程重启后找回可持续子任务。Provider 本地的子任务表会丢失已关闭子任务；不限定范围的 Session 列举可能暴露其他工作区或兄弟会话。

## 决策

选定的 Program 扫描现有持久化集合，并在发起 Session 的工作区内构造稳定的直接父子路径。普通 Session 与一次性子任务可以作为路径节点，但只有末端为 subagent 的候选会被检查和返回。检查先验证每条路径边、工作区及 subagent 委派深度，再由选定 Provider 折叠候选自身的描述符；中间节点无法读取时返回逐候选诊断。Provider 只返回自己的可持续子任务，以及实际 Program Agent 驻留状态或读取诊断。独立的原生工具在该 Provider 和可持续控制工具选定的同一 Tools 注册表上注册 `list_agents`。

## 考虑的替代方案

在 Provider 内镜像 Session 目录会创建另一份持久化权威。只使用在线 Agent 注册表会遗漏已关闭子任务。将存储的父 id 当成控制权限会让发现操作绕过直接消息准入。

## 后果

列表只读且不分页。直接子任务可作为消息候选；更深的条目仍需由控制操作独立授权。损坏或不受支持的候选产生诊断行，普通节点和一次性子任务中间节点保持隐藏。存储中的状态只是观察值，不保证后续投递成功。内置 SDK 与 ACP 配置显式安装工具；结束通知与未来的 `subagent.finished` 线路事件仍各自独立。
