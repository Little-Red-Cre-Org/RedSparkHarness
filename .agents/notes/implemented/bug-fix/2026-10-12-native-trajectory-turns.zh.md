# Agent Note：Native Trajectory 保留持久化轮次与计时

Status: implemented

[English](2026-10-12-native-trajectory-turns.md) | 中文

## 问题

Native Trajectory 从当前事件窗口构建记录表。仅投影消息会丢失没有助手消息的失败轮次；缺少持久化步骤计时的助手记录会从前一条可见消息估算耗时。

## 决策

Native 投影会在事件位置和请求记录中保留 `turn/start`、`turn/end`、步骤边界及助手尝试。助手消息计时使用匹配的持久化 `step/start` 时间戳。没有助手消息的失败轮次仍保留为单独轮次行及其失败请求记录。共享 layout 按事件位置记录的持久化轮次放置用户与上下文输入，仅在没有位置时才回退到其后的助手，因此失败轮次保留自己的提示词，而不会被并入下一轮。系统提示词单元同样使用其 `system/message` 事件记录的轮次，因此记录在失败轮次中的初始提示词不会再开启下一个成功轮次并导致顺序颠倒。只有属于已加载事件窗口中最早轮次的系统提示词才视为初始提示词，因此窗口从第 1 轮提示词之后开始时仍保持轮次顺序。窗口开头、尚无 `turn/start` 的 `user/message` 归入下一个记录了轮次的事件所属轮次，任何带轮次的事件也会为其后的输入设定当前轮次，因此失败轮次的提示词仍留在该轮。调用不在窗口内的工具结果使用其事件记录的轮次和步骤，而不再并入第 1 轮。

## 考虑过的替代方案

**根据相邻可见消息推算耗时。** 这样可能让助手跨度早于持久化步骤开始时间，并会随着无关消息而改变。

**只投影用户、助手和 Tool 结果事件。** 这样会丢失保留持久化轮次所需的轮次边界和空失败记录。

## 影响

Native 视图可使用 controller 已加载事件显示空失败轮次和准确的助手步骤开始时间。定向回归用例覆盖持久化助手计时，以及失败轮次后接成功轮次的情况，包括每轮提示词与系统提示词的归属；窗口用例覆盖窗口从首轮系统提示词之后、失败轮次的提示词、步骤中途或工具结果开始的情况。
