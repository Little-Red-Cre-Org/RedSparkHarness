# Agent Note: 在模块图被消费时生成客户端 combo

Status: implemented

[English](2026-10-16-desktop-startup-combo-materialization.md) | 中文

## 问题

桌面启动会逐步加载客户端插件。为每个中间图重建全部组合脚本和索引源码映射，会在浏览器消费这些图之前重复进行字符串扫描、序列化和内存分配。

## 决策

ClientModuleRegistry 在记录变化时同步校验排序和依赖，并保留已接受的表。首次图或 bundle 请求才生成该表的 combo 响应。后续读取复用相同的图和字节，直到接受下一次更新。无效更新保留已接受的表，现有上一代批次响应保留机制仍覆盖重载期间已公告的 URL。

## 考虑的替代方案

**Node 编译缓存**不能消除重复的 combo 拼接，也没有改善测得的本地启动路径。

**缓存单个产物和已完成批次**仍会为无人读取的中间图重建不断增长的 application 批次。

## 影响

首次读取需要一次 combo 拼接，因此仅测后端就绪时间不足以衡量收益。本地对比包含通过 Desktop 字节管道获取 index 和全部已公告的首批插件脚本，使用隔离的空 Harness home，不请求模型，也不包含浏览器绘制。现有模块注册表检查覆盖畸形输入、缺失依赖、环、不可变响应和源码映射重建。内存保留已接受的表及已生成的响应，而不为启动期间无人读取的中间图保存响应。
