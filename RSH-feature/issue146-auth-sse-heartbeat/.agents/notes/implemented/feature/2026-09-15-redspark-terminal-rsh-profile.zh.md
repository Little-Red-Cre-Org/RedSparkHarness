# Agent Note: RedSpark 终端 rsh profile

Status: implemented

[English](2026-09-15-redspark-terminal-rsh-profile.md) | 中文

## 问题

Shell 用户需要持续的终端对话，并复用现有 Agent、权限策略、预设和持久化 Session 存储。独立 Node 应用会绕过受支持的 profile 启动器。

## 决策

内置 `rsh` profile 组合 `dsh-base` 与 `dsh-rsh`。具名插件 `tui-runner` 等待 Loader 完成挂载，并拥有 Ink 应用和 Agent 句柄。预设挂载 Agent 作用域内的工具和提示词部分；`ask` 预设明确不提供工具。

渲染器从 Session 事件获取已完成输出，从 `agent/assistant-stream` 获取临时输出。失败尝试会清除临时输出。已接受的用户消息在后续排队工作被取消时保留其对话行。斜杠命令通过命令服务分发，不进入模型收件箱。模型与推理选择器通过 LLM 服务验证路由；权限变更使用现有命令。替换预设要求 Agent 空闲，并在释放原句柄前刷新原 Session。

渲染器在每个 Text 组件处过滤终端命令和控制字节，先使用 Node 的 VT 控制序列解析器，再移除剩余控制字节。仅过滤工具输出会让实时模型文本、存储的对话和审批原因仍能发出剪贴板或光标命令。Ink 在过滤后添加可信样式；持久化 Session 不受影响。

所属 Agent 的审批请求显示在终端中。用户选择 `y` 单次允许，或选择 `n` 拒绝。请求独立排队，中止或插件释放会取消待答请求。其他 Agent 的请求委托给下一个答复器。

正常退出会取消活动和排队工作，等待 Agent 空闲，并等待最终 Session 刷新完成后才请求启动器关闭。刷新失败会报告失败退出。启动器拥有有时限的整应用关闭流程；渲染器不强制退出进程。插件释放会移除终端监听器和定时器，并释放所属 Agent。

`rsh resume` 列出以 `session-` 为前缀的已存储会话，默认按调用目录筛选。持久化服务不能提供事件数时，列表读取完整历史，确保更新时间排序包含最后一个记录事件。直接恢复使用 `agents.resume`，并将已存储事件回放到对话中。该前缀也包含 headless 会话，并非 RSH 专属来源标记。

Windows 安装器创建绑定检出的 shell shim，转发到 `dsh --profile rsh`。它拒绝覆盖已有命令。界面派生自采用 MIT 许可证的 `gxinxing/deepseek-harness-tui`；包保留其许可证和第三方声明。

## 考虑过的替代方案

独立 npm 可执行程序会创建另一条应用启动路径。重新实现终端布局与输入需要维护比使用 Ink 更多的渲染代码。因此 profile 保留现有启动器，并使用持续维护的 React 终端渲染器。

## 验证

包测试覆盖参数解析、流转换、视口计算、先取消后刷新的顺序、刷新失败，以及挂载 Ink 后的命令分发、失败尝试清理和审批选择。构建与文档检查验证包集成。这些测试不能证明真实提供方的输出质量，也不能验证每种终端模拟器的渲染行为。

## 影响

终端会话共享基础安全策略和存储。输入框为单行，包不提供鼠标控制或会话级审批授权。恢复当前选择配置的默认模型，不从日志还原此前的路由。移动检出后需要重新安装 Windows shim。
