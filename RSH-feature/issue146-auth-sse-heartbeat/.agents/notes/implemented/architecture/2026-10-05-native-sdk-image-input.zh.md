# Agent Note: 原生 SDK 图片输入

Status: implemented

[English](2026-10-05-native-sdk-image-input.md) | 中文

## 问题

两套客户端和所选模型适配器已支持共享协议及附件词汇，原生 SDK 却拒绝编码图片块。

## 决策

原生 SDK 通过所选附件 Provider 消费既有编码图片协议。准入在创建用户消息之前校验并存储图片；既有 Session 执行器记录持久化引用。随附 native-sdk profile 安装本地附件存储，两套 SDK 通过既有 run 方法发送有序文本与编码图片块。pi-ai Provider 在每次派发时从这些引用读取已验证的请求变体。

## 考虑过的替代方案

把 base64 写入 Session 消息会绕过附件校验，并在历史中重复上传字节。独立的 SDK 图片存储会重复存储所有权与请求变换。既有附件能力无需这两种方案。

## 影响

非法上传在持久化收件回执及模型派发之前失败。冷恢复和分叉保留图片引用，并复用同一附件存储。所选模型仍负责拒绝不支持的图片能力。调用者提供的持久化引用和子代理通知不属于此原生 SDK 批次。一个既有录制 Session 场景驱动两套 SDK 验证上传拒绝、图片准入及冷恢复图片。
