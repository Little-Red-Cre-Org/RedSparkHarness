# Agent Note：原生 ACP 模型控制

Status: implemented

[English](2026-10-05-native-acp-model-controls.md) | 中文

## 问题

ACP 控制方需要标准的模型与推理配置，且不能创建传输私有的选择存储或另一 Session writer。

## 决策

新建和恢复的 Session 从所选原生模型目录与持久选择 Provider 投影配置选项。模型值编码完整的 provider/model 标识；推理值来自解析后的模型。当前持久路由在发现目录缺项时仍然可见。

配置请求按接收顺序串行执行。提示执行期间收到的请求等待该提示结算；下一提示不能越过待结算配置。调用方取消会拒绝等待的请求，同时保留前序操作的所有权。Session 关闭与传输 EOF 会取消并排空控制操作，再释放执行器。

共享执行器接收独占的空闲维护。选择 Provider 在维护内读取当前持久修订，校验实际路由、比较修订并刷写选择事件。ACP 承载方发布完整的最终配置，不保留第二份选择状态。

## 考虑过的替代方案

ACP 私有选择缓存会在冷恢复或另一 Program 的持久修改后产生分歧。模型执行期间写入意图会绕过已有维护所有者。硬编码模型列表会阻碍 Provider 驱动的配置。

## 影响

显式原生 ACP profile 支持模型与推理控制，legacy 默认保持不变。缺少目录或选择 Provider 时不展示选项并拒绝修改。MCP 挂载与权限交互仍是独立能力。
