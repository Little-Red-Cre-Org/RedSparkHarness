# Agent Note: 原生 SDK 下一步引导

Status: implemented

[English](2026-10-05-native-sdk-steering.md) | 中文

## 问题

原生 SDK 等待前一轮次结束后才执行普通排队提示。调用者无法在模型派发期间向已有下一步收件箱提交输入。

## 决策

原生专属 session/steer 方法和两套 SDK 将有序内容交给所选附件 Provider，再通过 Program 的精确活动根任务所有者排入 next-step，不唤醒另一驱动器。原始已接收轮次负责事件与取消。准入在上传之前检查轮次及根路由，上传之后再次检查原始所有者；取消或所有者释放会拒绝迟到输入。唯一写入者完成持久化后才响应。

## 考虑过的替代方案

取消当前派发再重启新轮次会改变引导行为并丢弃已接收输出。传输层自有队列会重复持久化收件箱，并在重启时丢失输入。已有活动 Session 能力同时提供所有权与持久化。

## 影响

引导输入不创建 Session，也不承诺模型答复。如果任务结算之前没有开始下一步，已接收的下一步输入会持久保留到恢复轮次。普通提示的排序不变。一个既有场景在暂停模型流期间提交引导，拒绝未知和空闲目标，取消后通过两套 SDK 恢复已记录输入。
