# Agent Note：共享原生 token 计量

Status: implemented

[English](2026-10-05-native-token-meter.md) | 中文

## 问题

原生 Program 需要维护中的 Session 回放测量，而不加载 Cordis Service 或创建另一估算器。原生执行器已准备提供方拥有的容量，须先记录该容量，消费方才能重建上下文占用。

## 决策

两种安装器委托给同一回放核心，保留用量锚定、请求头比较、有符号表面差值、不可变快照与逐 Session 所有权。Cordis Service 保留投影注册与准确文件文本回调。原生 Provider 读取所选模型的既有图片定价；缺少定价或原生文件投影时明确保持估算。测量元数据区分 usage、estimated 与空基线。

原始执行器 writer 从实际 dispatch 使用的同一已准备模型代际记录容量。路由或容量变化追加既有请求上下文事件；容量未知时替换旧值。已发布 Session 格式与已提交代际保持不变。

## 考虑过的替代方案

第二套原生估算器会与既有表面替换和提供方锚定语义分歧。另查目录获取容量可能将一个代际的元数据配到另一代际的 dispatch。虚构文件投影或 token 数会错误表述不可用能力。

## 影响

原生安装器保持显式，不创建 writer 或模型请求。兼容默认值不变。ACP 上下文用量传递是后续基于此服务与实际根 owner 的独立 Consumer 接入。
