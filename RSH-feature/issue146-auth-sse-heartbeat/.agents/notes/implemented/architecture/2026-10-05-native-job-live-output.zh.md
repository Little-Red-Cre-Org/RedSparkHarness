# Agent Note：原生任务保留 Producer 已观察的实时输出

Status: implemented

[English](2026-10-05-native-job-live-output.md) | 中文

## 问题

原生任务控制需要在后台 runner 完成前读取真实输出。PTY 输出已通过共享清理器，但原生注册表仅收到最终展示文本。

## 决策

选定的原生 Jobs 注册表为每个 runner 提供文本发布回调。现有 UTF-8 TextRetainer 限制可配置的单任务尾部预算。读取不消费文本；取消或完成后发布失效。runner 仍在所属清理完成后结算；显式最终输出替换实时展示，并保留 Producer 的截断事实。

共享 PTY send 操作在清理后的文本到达时通知请求观察者，不消费自身 viewport。原生终端 runner 直接发布这些文本。不引入定时器、进度估算或第二任务注册表。其他 runner 可以仅提供最终输出，不发布实时文本。

现有 job_output 值工具读取保留输出，附带截断元数据，并在展示预算内保留状态行。应用在下一次模型请求前将选定 ToolResult 记录到唯一 Session；未读取输出对模型不可见，不需要单独事件流。

## 后果

重复读取可以重复保留文本。PTY 保留与最终格式化仍受自身预算限制；省略文本会明确标记，不表示结果完整。任务仍要求协作式取消，不能超出其精确 Agent owner 的生命周期。

## 考虑过的替代方案

轮询 PTY 会消费 viewport 或增加输出 owner。记录每个异步文本块会为模型未读取的文本创建多余的持久流。直接发布与标准工具读取保留现有所有权和 Session 规则。
