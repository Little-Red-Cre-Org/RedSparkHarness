# Agent Note：原生 Web 图片保持根准入与持久化身份

Status: implemented

[English](2026-10-05-native-web-image-admission.md) | 中文

## 问题

原生浏览器对话需要让上传图片到达选定模型，并在重新加载后保持可见。浏览器持有的字节无法重建模型历史；独立的图片预检可能与 Session 内的模型选择竞争。

## 决定

根执行器在既有执行所有者内接受仅供根调用的输入准备回调。准备过程在 inbox 准入前取得实际下一模型路由及组合取消信号，返回带身份的用户消息，不获得写入者访问权。它优先于直接消息输入。Web 解析该路由的图片能力，再通过选定附件 Provider 将有序上传提升为持久化引用。准备失败不会准入用户输入或模型请求。

经过身份认证的图片端点搜索完整 Session 历史，包括继承的图片引用，并在访问存储前核对配置的工作区。不接受调用方提供的引用及文件系统路径。附件 Provider 验证已记录图片，并在配置的图片限额内返回光栅字节。浏览器验证响应媒体类型及长度，并拥有读取取消与 Blob URL 释放。

## 考虑过的替代方案

仅在浏览器内预览会遗漏可重建的模型输入。先维护再根执行会在两项操作之间留下模型选择竞争；在维护内嵌套执行则会死锁。第二套图片注册表会重复持久化附件身份。既有根所有者与附件 Provider 同时提供准入及存储能力。

## 影响

显式 native-web profile 保留旧默认装配，并公布选定 Provider 的限额。提交的消息需要文本，可包含图片；文件及音频仍属于独立工作。共享原生渲染器可装配到 Desktop，但实际原生 Desktop 装配及 GUI 验收仍属于独立工作。冷恢复只展示持久化 Session 历史中的图片。
