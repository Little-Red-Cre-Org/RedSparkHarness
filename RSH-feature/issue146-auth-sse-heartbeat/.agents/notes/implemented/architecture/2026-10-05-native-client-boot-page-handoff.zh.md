# Agent Note：原生 Client 启动页交接

状态：已实现

[English](2026-10-05-native-client-boot-page-handoff.md) | 中文

## 问题

独立的 `native.html` 入口加载 Host 选中的 Client 模块并挂载渲染器，但导入等待期间页面为空白。失败时它使用无样式的替换元素显示错误。现有产品 `index.html` 已有无框架启动页；原生页面需要相同的可见安装生命周期，同时不能导入 Cordis 外壳。

## 决策

将 DOM/CSS 启动页作为独立浏览器入口发布。原生 Client 安装器通过可选回调报告选中模块的导入、失败和完成激活。应用入口把这些状态投影到启动页，在渲染器交接失败后重新挂载启动页，并在成功挂载或文档卸载后释放它。现有产品入口继续使用其 Cordis Loader 和 UI 名册。

启动页入口将样式表作为包资源保留，交给应用打包器处理。`native` 入口保持现有运行时依赖图，不静态导入启动页或任何 Cordis 模块。

## 考虑过的替代方案

**导入主 Web 外壳：** 否决，因为这会把 Cordis context 和 Loader 加载到原生页面。

**在应用内复制启动页：** 否决，因为两个入口页面的失败呈现和样式会逐渐分歧。

## 结果

选中的原生 Client 图有可见的加载与失败状态，并只进行一次渲染器交接。这不会迁移受支持的产品 UI 名册，也不改变默认页面。原生 UI 仍需 Host 选择渲染器和应用 Provider。

## 验证

聚焦的 native-entry 用例验证初始模块进度与导入失败。真实浏览器加载已编译的原生入口，验证加载、渲染器交接、pagehide 清理和失败呈现，同时未请求 Cordis。
