功能02 浏览器只读接入报告说明

当前没有可直接从日常快捷方式打开的浏览器功能入口。IDE 截图来自10月10日完成的离线验收；当前复核发现旧验收启动脚本依赖的临时桌面配置已不在原路径，因此旧脚本不能作为现成入口。下文提供源码版本支持的 Native profile 配置方式。

二 真实界面与入口

此功能没有独立管理页面。你会接触两个地方：Chrome 的扩展弹窗，以及 RSH 的现有会话与工具审批界面。下列均为实际验收截图，不是设计效果图。

Chrome 弹窗中的按钮

  • 连接：连接已运行且已安装浏览器模块的 Harness Host。
  • 授权当前页：为当前网页创建授权。仅列出授权页面，不列出所有标签页。
  • 撤销：撤销该页面授权，后续读取将拒绝。
  • 断开连接：清除全部授权。下次连接后需要重新授权。

图中 localhost 地址是验收网页，不是打开 RSH 的固定地址。不要复制它作为应用入口。

三 首次配置与打开方式

下列步骤面向这个功能分支的已构建源码版本，需要 Node.js、pnpm 和 Windows Chrome。配置步骤依据随包中文指南整理；它们不是本次新执行的日常安装记录。本次交付仅生成说明材料，没有注册你的日常 Chrome，也没有修改默认 profile。

1 创建独立 Native 会话配置

在 PowerShell 中执行以下命令。使用单独的 DSH_HOME，以便与日常会话数据分开。首次启动创建 profile 后，用 Ctrl+C 停止该实例，再进行下一步。

Set-Location 'E:\redsparkHarness\RedSparkHarness-zero-budget-next'
$env:DSH_HOME = Join-Path $env:LOCALAPPDATA 'RedSparkHarness\browser-read-only-trial'
pnpm dsh --profile native-web

若提示已有程序包尚未构建，应先完成对应源码构建。浏览器包的构建命令如下；这两条只负责浏览器包，不代替整个桌面应用构建。

pnpm exec tsc -b rsh/Modules/Official/web/browser-read-only
pnpm --dir rsh/Modules/Official/web/browser-read-only exec tsdown

2 在会话 Host 中安装浏览器模块

仍在同一个 PowerShell 窗口执行：

Set-Location (Join-Path $env:DSH_HOME 'profiles\native-web')
pnpm add 'link:E:/redsparkHarness/RedSparkHarness-zero-budget-next/rsh/Modules/Official/web/browser-read-only'

打开 $env:DSH_HOME/profiles/native-web/rsh.profile.json，在现有 installations 数组中加入下面这个对象，保留其他条目并正确处理逗号。不要用这个对象覆盖整个配置文件。

{
  "id": "browser-read-only",
  "plugin": "@deepseek-ai/dsh-browser-read-only",
  "scope": "root",
  "config": {
    "connectionFile": "C:/Users/12148/AppData/Local/RedSparkHarness/browser-read-only/connection.json"
  }
}

路径示例对应当前 Windows 用户 12148；若运行账号不同，请替换为该账号的私有本地应用数据目录。保留现有工具、审批服务与会话应答方。模块应装在会话 Host 的 profile 中，不要仅加入独立的 native-ide 编辑器 profile，也不要写入 cordis.yml。

3 启动同一个 Host 并注册 Chrome 连接

返回源码根目录，在保留上述 DSH_HOME 的 PowerShell 窗口中启动：

Set-Location 'E:\redsparkHarness\RedSparkHarness-zero-budget-next'
pnpm dsh --profile native-web

按终端实际输出打开应用地址，不使用截图中的测试端口。会话使用的真实模型与凭据需在该独立配置中按现有模型设置完成；不要把离线 fixture 当成日常模型。

保持 Host 运行，在另一个 PowerShell 窗口执行：

Set-Location 'E:\redsparkHarness\RedSparkHarness-zero-budget-next'
$connectionFile = Join-Path $env:LOCALAPPDATA 'RedSparkHarness\browser-read-only\connection.json'
& '.\rsh\Modules\Official\web\browser-read-only\scripts\register-chrome.ps1' -ConnectionFile $connectionFile

注册命令的 connectionFile 必须与第2步一致。连接文件含本地认证令牌，保存在用户私有目录，不复制到对话或截图中。已存在其他安装的注册项时，脚本会拒绝覆盖，应先按其原安装方式处理。

4 在 Chrome 加载扩展

  1. 打开 chrome://extensions。
  2. 开启“开发者模式”，点击“加载已解压的扩展程序”。
  3. 选择下方目录，确认扩展名为 RedSpark Harness Read Only。
  4. 将扩展固定到工具栏。打开普通 HTTP 或 HTTPS 网页，点击扩展图标，或使用建议快捷键 Alt+Shift+R。

5 如果要在 IDE 内使用

先为 Native Desktop 的会话 Host 安装同一浏览器模块，再从空闲会话点击“在 IDE 中打开”。IDE 内的嵌入会话复用该 Host 的审批和 Session。独立 native-web 的配置不会自动转换日常 Desktop，也不会自动生成截图中的 IDE 桌面环境。

四 每次如何使用

  1. 启动：启动安装了浏览器模块的同一 Native Host。若新开 PowerShell，需要重新设置前述 DSH_HOME。
  2. 授权：在 Chrome 打开目标网页，点扩展的“连接”，再点“授权当前页”。核对列表中的标题和网址。
  3. 提问：在 RSH 当前会话输入下方示例请求。只有授权页面会出现在 browser_tabs 中。
  4. 审批：出现 browser_read 工具审批时，点击“允许一次”。不希望正文进入会话时点击“拒绝”。
  5. 查看：展开 browser_read 工具结果，检查 title、url、text 和 truncated。truncated 为 true 表示正文被长度限制截断。
  6. 结束：在扩展点“撤销”或“断开连接”。刷新、导航、关闭页面后原授权失效，需要重新授权。
读取已授权的浏览器页面，并引用来源网址。
